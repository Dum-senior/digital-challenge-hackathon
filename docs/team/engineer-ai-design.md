# Помощник инженера

14.11.2026. Направление согласовано владельцем проекта; выбор деталей и публикация feature-ветки делегированы разработке. Две независимые проверки выполнены до реализации; замечания учтены ниже.

## Поведение

Сотрудник запускает помощника в карточке заявки. Он получает опубликованные инструкции и отмеченные решения доступных закрытых заявок. При включённой генерации модель предлагает до шести шагов со ссылками. Применение рекомендаций подтверждает инженер; заявка автоматически не меняется.

Конфиденциальная текущая заявка возвращает 403 для любой роли, до поиска и обращения к модели. Конфиденциальные, объединённые и закрытые без решения архивные заявки исключаются. Права проверяются сервером для текущего сотрудника; общий кеш ответов не используется.

## Контракт

`POST /api/v1/tickets/{id}/engineer-assist`: существующий Bearer-токен сотрудника, тело не требуется. Сессионный маршрут `POST /agent/tickets/{id}/engineer-assist` используется и администратором; требует входа и `_token` CSRF. Оба вызывают один PHP-модуль.

Успешный ответ содержит `ticket_id`, `status`, `requires_human_review: true`, `steps` и `sources`. Шаг: `{text, source_ids}`. Источник: `{id, kind, title, url, excerpt}`; ID имеют вид `kb:17` или `ticket:23`. Адрес, заголовок и выдержка формируются только сервером, адрес заявки выбирается по роли вызывающего пользователя. Ссылка на решение включает `#timeline-entry-ID`.

- `answered`: модель вернула 1–6 корректных шагов.
- `sources_only`: источники есть, но генерация выключена, не настроена, отказала или вернула некорректный ответ.
- `no_sources`: подходящих источников нет; модель не вызывается.
- HTTP 400: неверный ID; 401: нет входа; 403: нет доступа, CSRF или конфиденциальность; 404: заявка отсутствует; 429: более пяти запросов на сотрудника в минуту; 503: поиск или его ограничитель недоступен. Ошибки имеют поле `error`; 503 дополнительно обозначается `status: unavailable`.

Оба маршрута возвращают `Cache-Control: private, no-store`. Лимит общий для API и браузера: существующая таблица `api_rate_limits`, ключ `engineer-assist:USER`, фиксированное окно 60 секунд, без отказа в открытый доступ при сбое БД. Кнопка блокируется до завершения запроса. Автоматических повторений нет.

## Поиск и модель

Из первых 4000 символов темы/описания выделяются до восьми уникальных слов длиной 3–64 символа, в нижнем регистре, без распространённых служебных слов. Опубликованные статьи ищутся параметризованным LIKE по заголовку и тексту: совпадение заголовка весит 2, текста — 1; сортировка по сумме и ID, максимум три статьи. Это лексический поиск без морфологии; на большой базе его следует заменить индексированным поиском после замера.

Архив использует существующий FULLTEXT по теме/описанию, `ticketStaffVisibilitySql()`, `ticketClosedBucketSlugs()` и `ticketStatusSqlIn()`. Условие решения: `tl.id = t.solution_timeline_id AND tl.ticket_id = t.id AND tl.action = 'comment'`. `close_reason IS NULL`, непустой нормализованный текст, максимум три источника из 20 кандидатов, порядок FULLTEXT relevance DESC, ID ASC. Статусы не зашиты строками. Внутреннее отмеченное решение допустимо только для сотрудника с доступом к этой заявке.

Выдержка ограничена 1200 символами. Ollama получает до пяти источников, контекст 4096 токенов, лимит ответа 420 токенов и тайм-аут 25 секунд.

Генерация требует ENGINEER_AI_GENERATION_ENABLED=true. URL и модель задаются через ENGINEER_OLLAMA_URL и ENGINEER_OLLAMA_MODEL. По умолчанию используется qwen3:0.6b.

Ответ модели должен быть JSON-объектом с единственным полем `steps`, максимум шесть шагов; шаг содержит только `text` (1–1000 символов) и `source_ids` (1–6 существующих ID). Любой ошибочный шаг отклоняет ответ целиком. Размер сырого ответа ограничен 16 КБ. Документы в запросе помечаются как недоверенные данные. В интерфейсе весь текст вставляется через `textContent`. Валидная ссылка не доказывает достоверность совета — это ограничение указано рядом с результатом.

Журнал: существующий `logAudit()` с явным ID сотрудника; сохраняются состояние, ID источников и время, без текстов заявок, документов, ответов провайдера или ключей.

## Рассмотренные варианты

Расширить `findSimilarPastTickets()` напрямую неудобно: оно зависит от включённого ИИ, вызывает модель, использует кеш и включает открытые заявки. Поэтому переиспользуются его SQL-правила, а не вся функция. Отдельный Python/vector-сервис потребовал бы синхронизации прав и нового развёртывания. Выбран небольшой PHP-модуль; ограничение — лексический поиск, особенно русские словоформы. Локальная модель остаётся отдельным этапом.
