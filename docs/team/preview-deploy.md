# Командный стенд

Стенд доступен по HTTPS на IP сервера. Для публикации используйте проверенный
коммит из интеграционной ветки. Текущая схема обновления ручная.

## Компоненты

- Nginx обслуживает `/srv/helpdesk-preview/public` и передаёт маршруты в PHP 8.3 FPM.
- MariaDB слушает localhost. База `helpdesk_preview` и пользователь выделены для стенда.
- Whisper работает на том же хосте. PHP обращается к
  `http://127.0.0.1:8090/inference`. Порт Whisper остаётся локальным.
- HTTPS использует короткоживущий сертификат для IP. Certbot проверяет продление
  дважды в день и перезагружает Nginx после обновления сертификата.

## Подготовка

Установите Nginx, PHP 8.3 FPM с PDO MySQL, cURL, mbstring, XML и ZIP, Composer,
MariaDB и FFmpeg. Настройте корень сайта на `public/` и направляйте запросы
в `public/index.php`. Запретите веб-доступ к `/install`, прямой доступ к
`/uploads` и выполнение остальных PHP-файлов из веб-корня.

Создайте отдельную пустую БД и пользователя с правами только на неё. Заполните
серверный `.env` по `.env.example`. Укажите HTTPS-адрес стенда в `APP_URL`,
задайте `MAIL_ENABLED=false`, `APP_DEBUG=false` и настройте
`STT_WHISPER_URL` по [инструкции STT](voice-ai.md). Веб-процессу нужны чтение
конфигурации и запись в `storage/` и `public/uploads/`. Установите
`upload_max_filesize=20M` и `post_max_size=21M` в PHP и `client_max_body_size 21m`
в Nginx.

Для первого запуска установите зависимости командой
`composer install --no-dev --prefer-dist --no-interaction`. Если нужны
демо-учётки, запустите `php database/seed.php` **только на новой пустой
базе стенда**. При обновлениях seed не запускается.

## Обновление и проверка

1. Зафиксируйте текущий SHA и сделайте резервную копию базы перед релизом с миграциями.
2. Подготовьте выбранный SHA и зависимости в отдельном каталоге. Подключите
   серверный `.env` и существующие данные `storage/` и `public/uploads/`.
3. Переключите Nginx на новый `public/` после `nginx -t` и перезагрузите Nginx.
   При ошибке верните предыдущий корень. Если прошли несовместимые миграции,
   восстановите базу из соответствующей резервной копии.
4. Проверьте HTTPS, вход под демо-учёткой и отправку записи с Bearer-токеном.
   Запрос без токена должен вернуть 401.

Проверка текущего стенда подтвердила HTTPS 200, STT 401 без токена и
успешное распознавание тестового WAV через авторизованный API.

## Автодеплой и тесты команды

Стенд отслеживает ветку `codex/preview-autodeploy` с интервалом в минуту.
На сервере systemd запускает установленную копию `deploy/preview-update`.
Скрипт готовит новый релиз отдельно, переключает ссылку на него и возвращает
предыдущий релиз при ошибке HTTP-проверки. База, загрузки и настройки общие
для релизов. Откат ссылки не откатывает миграции БД.

Интеграционные тесты добавляйте через PR в `codex/preview-autodeploy`.
Для запуска используйте изолированное окружение `compose.test.yaml` по
[инструкции команды](README.md). Сброс БД и seed запускайте только в нём.
