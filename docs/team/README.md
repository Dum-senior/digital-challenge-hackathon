## Помощник инженера

В карточке заявки у инженера и администратора есть кнопка **«Найти решение»**. Она ищет опубликованные статьи по заголовку и тексту, а также доступные закрытые заявки с отмеченным решением. В результатах есть выдержки и ссылки на статьи или конкретную запись решения.

По умолчанию работает локальный поиск. Для ИИ-шагов настройте существующий провайдер в Admin → Settings → AI и установите `ENGINEER_AI_GENERATION_ENABLED=true` в окружении приложения. Это разрешает отправку текста текущей заявки, найденных выдержек базы знаний и отмеченных решений выбранному провайдеру. Конфиденциальные заявки помощник не обрабатывает даже для администратора.

При отключённой/недоступной модели сохраняются источники. Выдуманные ID и некорректный формат ответа отклоняются целиком. Проверять содержание совета должен инженер; помощник ничего не меняет в заявке.

Для Дена: после сохранения и проверки заявки вызовите `POST /api/v1/tickets/{id}/engineer-assist` с Bearer-токеном текущего сотрудника. Не используйте общий административный токен вместо идентичности пользователя. Тело запроса не нужно. Ответ: `ticket_id`, `status`, `requires_human_review`, `steps`, `sources`. `status` бывает `answered`, `sources_only` или `no_sources`; ошибки возвращаются соответствующим HTTP-кодом и полем `error`. Лимит — пять запросов на сотрудника в минуту, общий для API и браузера; 429 содержит `Retry-After`.

Для Вани и Кирюхи: в исходном `src/bootstrap.php` стоит `Permissions-Policy: ... microphone=()`. Для записи голоса нужно согласованно разрешить микрофон на нужном origin. В этой ветке политика не менялась.

## Локальный запуск и проверки

Нужен запущенный Docker. Окружение ниже предназначено только для разработки. Оно использует отдельный том с БД `engineer_test`, отключает отправку почты и публикует веб-сервер только на `127.0.0.1:8085`. Локальный `.env` заменяется внутри контейнера файлом `docker/test.env`, поэтому тесты не берут реквизиты рабочей БД из вашего `.env`.

```sh
touch .env
docker compose -f compose.test.yaml build app
docker compose -f compose.test.yaml up -d db
docker compose -f compose.test.yaml run --rm app composer install --no-interaction --prefer-dist
docker compose -f compose.test.yaml run --rm app php database/seed.php
docker compose -f compose.test.yaml up -d app
docker compose -f compose.test.yaml exec app vendor/bin/phpunit --filter EngineerAssistant
```

`database/seed.php` сбрасывает данные: запускайте его здесь только при первоначальном создании или намеренном сбросе тестовой БД. Он предложит задать пароли для демонстрационных admin/agent/user. Для входа откройте http://localhost:8085 и используйте `admin@localdesk.user` и заданный пароль.

Для ручного примера опубликуйте статью о проверке очереди печати. Создайте заявку «Принтер не печатает», добавьте описание симптомов и нажмите кнопку помощника. Для проверки архива добавьте похожую заявку, запишите результат в комментарии, отметьте его как решение и закройте заявку. Сам факт закрытия без отмеченного решения в подсказки не попадает.

Остановка: `docker compose -f compose.test.yaml down`. Данные остаются в отдельном томе. `down -v` дополнительно удаляет именно тестовый том.

## Ограничения

Поиск лексический: словоформы, синонимы, короткие обозначения и ошибки распознавания могут давать пропуски. В запрос берутся первые восемь значимых слов; отображаются до трёх статей и трёх решений. Выдержки выбираются из первых 24 000 символов материала и ограничены 1200 символами. Сопоставление текста очень длинных статей пока выполняется без отдельного полнотекстового индекса.

PDF/OCR, загрузчик файлов в базу знаний, локальная языковая модель и модули других участников не реализованы этой веткой. Текущие инструкции должны быть заведены как статьи OpenHelpDesk. Настоящий ответ облачной модели требует отдельной проверки после настройки ключа; автоматические тесты используют подмену провайдера.
