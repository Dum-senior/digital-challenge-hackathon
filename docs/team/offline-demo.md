# Офлайн-демо помощника инженера

Установите Ollama на хосте и заранее выполните `ollama pull qwen3:0.6b`. Других моделей не требуется. В Docker Desktop адрес хоста для приложения — `http://host.docker.internal:11434`. На Linux сервере используйте приватный адрес Ollama, доступный из контейнера приложения. Привяжите Ollama к приватному интерфейсу и ограничьте доступ адресами контейнеров. Порт 11434 не нужно публиковать в интернет.

Проверка готовности Ollama выполняется командой `curl -fsS http://127.0.0.1:11434/api/tags` на хосте. Убедитесь, что в списке есть `qwen3:0.6b`. Если модель не помещается в память, проверьте журнал Ollama на ошибки загрузки и освободите память. При ошибке или тайм-ауте помощник продолжает показывать найденные источники.

После инициализации изолированной базы по [инструкции команды](README.md) выполните:

```sh
ENGINEER_AI_GENERATION_ENABLED=true docker compose -f compose.test.yaml up -d app
docker compose -f compose.test.yaml exec -T -e ENGINEER_DEMO_SEED=yes app php database/seed_engineer_demo.php
```

Повторный запуск сохраняет существующие записи. Скрипт работает с БД `engineer_test` и добавляет 20 учебных статей и 8 синтетических закрытых заявок. Не используйте `down -v`, если хотите сохранить данные.

После сохранения заявки внешняя интеграция может вызвать `POST /api/v1/tickets/{id}/engineer-assist`. Кнопка в карточке вызывает сессионный маршрут POST `/agent/tickets/{id}/engineer-assist`. Голосовой модуль и диспетчер смогут передавать текст в обычный процесс создания заявки после объединения веток. Ответ содержит прежние поля `ticket_id`, `status`, `requires_human_review`, `steps` и `sources`. В `steps` используются ID из `sources`. Поиск работает на MariaDB, включая FULLTEXT для архива. Для проверки создайте заявку «Принтер не печатает» или «Нет связи с контроллером» и нажмите «Найти решение».
