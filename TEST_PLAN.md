# Проверки Frontend V4.2

## Новые проверки V4.2

- [ ] Новая обычная заявка: часы + «Не выполнено».
- [ ] Принятая заявка: инструмент + «Работа выполняется».
- [ ] Заявка с `repairRequired=true`, `status=open`: иконка ремонта + «Требует починки».
- [ ] Завершённая заявка: зелёная галочка + «Выполнено».
- [ ] Для критической заявки до принятия отсутствуют все соседние статусы, есть только мигающее «СРОЧНО ПРИНЯТЬ»; после принятия появляется «Работа выполняется». Кнопка «Выполнено» также должна отсутствовать в критической непринятой строке.
- [ ] При `prefers-reduced-motion=reduce` инструменты и тревога не анимируются, но подписи сохраняются.

## Проверено в изолированном браузерном прогоне

- [x] После «СРОЧНО ПРИНЯТЬ» сигнал исчезает, отображаются «Критический» и «В работе», кнопка завершения доступна.

- [x] Диспетчер: сценарий дыма → критический анализ, форма извлечённых полей и ручной правки.
- [x] Инженер: в списке есть красная мигающая «СРОЧНО ПРИНЯТЬ» и SLA-таймер на критической непринятой заявке.
- [x] Нажатие «СРОЧНО ПРИНЯТЬ» переводит заявку «В работу» и прекращает тревогу.
- [x] Нажатие «Выполнено» завершает уже принятую заявку.
- [x] Кнопка создания новой тревоги в DEMO отображает новую критическую заявку.
- [x] Администратор: запрос статистики, графики по приоритетам и статусам.
- [x] Администратор: загрузка журнала действий.
- [x] Администратор: секундомер ручного сценария и остановка замера.
- [x] Мобильный рендер 375px (скриншот); CSS без внешних CDN.

## Проверить после подключения API

- [ ] Полный сценарий «текст/голос → ИИ → проверка диспетчером → заявка → инженер → RAG → завершение».
- [ ] Вход и разграничение прав для 3 ролей; невидимость чужих заявок инженеру.
- [ ] Уверенность ИИ и извлечённые поля корректно приходят от модели, их правки сохраняются.
- [ ] SLA рассчитывает сервер, при обновлении страницы дедлайны не сдвигаются.
- [ ] Новый критический запрос появляется у инженера без ручного refresh (polling ≤ 15 сек).
- [ ] Скриншот безопасно прикрепляется или показывается честная ошибка отсутствующего API.
- [ ] По дыму срабатывает правило безопасности при недоступности LLM.
- [ ] По «100 принтеров» высокая срочность с гипотезой общей причины.
- [ ] Нет краски — низкая срочность.
- [ ] «Не работает» — уточнение, без выдуманных полей.
- [ ] Источники RAG являются ссылками на настоящие записи БД.
- [ ] Статистика, журнал и SLA проверены по настоящим значениям MariaDB.
- [ ] Веб-интерфейс и модели работают в закрытой сети; микрофон — по HTTPS/localhost.
- [ ] Снижение анимации `prefers-reduced-motion: reduce`: тревога остаётся заметной без мигания.

## Дополнительно

Надёжность сквозного теста требует отдельного стенда. Демо-режим использует учебные данные в `localStorage`, а не настоящие звонки, запросы LLM и записи БД.
