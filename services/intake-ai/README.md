# 02_ДЕН — ИИ-диспетчер (изолированный модуль)

Сервис `text|voice|phone -> структурированный анализ -> рекомендация -> ручная проверка` для интеграции с PHP OpenHelpDesk. НЕ заменяет OpenHelpDesk и не создаёт итоговую заявку. Ориентир: `00_КОМАНДА_НАЧАТЬ_ЗДЕСЬ.md` и `02_ДЕН_ИИ_ДИСПЕТЧЕР.md`.

## Что уже реализовано

- Авторизованный `POST /api/hackathon/v1/intake/analyze`, вход `{text, source}`. Все входы проходят одну функцию.
- Поля `object/site/building/floor/room/ip/equipment/meter_number/serial_number/incident_time/error_code/symptoms/scope`. Если данных нет, поле `null`; модель может дополнить только дословные фрагменты исходного обращения.
- Русские категории и детерминированная классификация опасных случаев; приоритет с объяснением и предупреждением. Неполные запросы требуют уточнения.
- Рекомендация существующего инженера ТОЛЬКО из **доверенного** переданного PHP-каталога групп, навыков, доступности и нагрузки. При отсутствии каталога IDs `null`. Ни одна функция не назначает инженера самостоятельно.
- Простой риск SLA по известному deadline от OpenHelpDesk: `unknown`, `on_track`, `warning` (<=30 минут), `breached`. Это демонстрационная политика, не норматив Газпрома и не статистический прогноз.
- OpenAI-совместимый локальный LLM-сервер; включается только явно, по умолчанию правила без выдуманной LLM. Невалидный JSON, timeout или отключение модели -> `status=failed`, `analysis_mode=rules_fallback`, запрещена рекомендация конкретного инженера, ручной путь остаётся доступным.
- `analysis_id` — идентификатор анализа, НЕ идентификатор сохранённого черновика. `draft_id=null`/`persisted=false` до сохранения через существующую OpenHelpDesk PHP-часть. Нельзя выдавать этот сервис за завершённую интеграцию.
- Токены отдельно для PHP -> intake и intake -> LLM, строго из окружения. Никаких секретов в git и логах.

## Установка — только uv (никакого pip)

```bash
cd services/intake-ai
uv sync --group dev             # разрешает зависимости и создаёт uv.lock (нужен доступ к PyPI)
# значения секретов генерируйте на целевом сервере, не копируйте шаблонные строки
export INTAKE_SERVICE_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
export ENABLE_LLM=false
uv run pytest -q
uv run python -m intake_ai
```

Интерфейс по умолчанию слушает **только** `127.0.0.1:8091`. Пример вызова (с токеном из server-only окружения):

```bash
curl --fail-with-body -X POST http://127.0.0.1:8091/api/hackathon/v1/intake/analyze \
 -H "Authorization: Bearer $INTAKE_SERVICE_TOKEN" \
 -H "Content-Type: application/json" \
 -d '{"text":"На НТП с 09:00 нет данных счётчика","source":"text"}'
```

Ожидаемые поля: `status`, `analysis_id`, `draft_id`, `persisted`, `category`, `priority`, `priority_reason`, `fields`, `missing_fields`, `recommended_team_id`, `recommended_engineer_id`, `sla_risk`, `safety_warnings`, `confidence_notes`, `requires_human_review`. В ответе `draft_id` всегда null — сохранение принадлежит PHP-интегратору.

## Настоящая локальная модель

Это **приватное развёртывание модели с открытыми весами**, а не закрытая проприетарная модель. Для размещения без передачи запросов в чужое облако предлагается Qwen3-8B с vLLM (GPU) либо llama.cpp (в том числе квантизованный CPU/GPU) через тот же OpenAI-compatible `/v1/chat/completions`.

1. Разверните инференс внутри закрытой сети/на loopback, ограничьте доступ к **ВСЕМ** endpoint-ам сетевым фильтром/reverse proxy; `--api-key` vLLM не закрывает все его маршруты.
2. Создайте два **разных** криптостойких токена на хосте, сохраните в отдельном файловом хранилище секретов/переменных, доступном только service account: `INTAKE_SERVICE_TOKEN`, `LLM_API_KEY`. Поскольку сервер ещё не куплен, действующий токен пока нельзя безопасно выдать или проверить. Генератор приведён выше. Не показывайте настоящие токены в чате.
3. Укажите в server-only окружении `ENABLE_LLM=true`, `LLM_BASE_URL=http://127.0.0.1:8000/v1`, `LLM_MODEL=Qwen/Qwen3-8B`, `LLM_API_KEY=<server-only secret>`. Убедитесь, что инференс запущен с ТЕМ ЖЕ LLM API-токеном.
4. Перезапустите только сервис Дена; проверьте тестовое обращение, зафиксируйте время ответа и качество на 10 кейсах **с реальной моделью**. Тесты ниже используют подмену провайдера, не подтверждают качества реальной LLM.

Не передавайте в сервис реальные записи и персональные данные до аудита доступа, согласия, сетевой изоляции и политики хранения.

## Отдельные потоки

- Ваня передаёт **исправленную транскрипцию** как `source=voice`.
- Кирюха после Вани передаёт текст телефонной записи как `source=phone`.
- Дмитрий/интегратор вызывает сервис с текущей авторизацией OpenHelpDesk на стороне PHP, сохраняет черновик и проводит подтверждение, после чего работает инженерный RAG.
