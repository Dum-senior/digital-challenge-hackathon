# Ден — ИИ-диспетчер

Изолированный модуль задачи 02 в ветке `feature/dispatcher-ai`. В исходном main на момент начала был только README (commit abcabc53fe4d92ee3172357d66a5b6e8ff06188f). Поэтому интеграция с реальным OpenHelpDesk пока не проверена: этот сервис не заменяет приложение команды.

## Границы

Наш код: текст/транскрипт → проверенное предложение полей, категории, критичности, вопросов и исполнителя. Один контракт для text/voice/phone. Нет STT Вани, телефонии/общего CI Кирюхи, RAG/БД/интерфейса/назначения интегратора. Каталог инженеров поступает из доверенного серверного адаптера. Встроенной базы пользователей нет.

## Запуск через uv

Из этой папки:

```powershell
uv sync --frozen
uv run python tools/init_secrets.py
uv run uvicorn app:app --host 127.0.0.1 --port 8010
```

Генератор не перезаписывает существующий `.env` и не печатает значения. На этой машине uv установлен в `C:\Users\1\.local\bin\uv.exe`; новый терминал должен использовать соответствующий PATH либо полный путь. `pip` не используется.

В `.env` установить LLM_BASE_URL и LLM_MODEL реально работающего inference-сервера. LLM_API_KEY должен совпадать с ключом, который этот сервер проверяет. Сгенерированный ключ не даёт доступа к чужому провайдеру и не означает, что сервер уже развёрнут. DISPATCHER_API_TOKEN — отдельный ключ для вызовов вашего backend → модуль Дена. Секреты нельзя помещать в JavaScript браузера, аргументы команд, Git или скриншоты.

## Вызов

`POST /api/hackathon/v1/intake/analyze`, `Authorization: Bearer <DISPATCHER_API_TOKEN>`, JSON:

```json
{"text":"На НТП с 09:00 нет данных счётчика","source":"voice"}
```

Возвращает `needs_clarification`, `awaiting_review` или `failed`. Сервис не сохраняет черновики: draft_id — correlation ID предложения, не ID записи в БД. Интегратор должен сначала сохранить исходное обращение, затем результат анализа, и обеспечить ручное подтверждение. При failed исходный текст остаётся у вызывающего backend, который открывает ручную обработку. Никаких автоматических назначений.

Схема входа/выхода доступна в `/openapi.json`; `/docs` — техническая документация. `/health` проверяет процесс, а не модель. HTTP 401 — нет токена; 422 — неверный вход; 503 — невалидный каталог инженеров. Сбой inference отражается статусом failed, не поддельным результатом.

Справочник: ENGINEERS_FILE указывает на UTF-8 JSON-массив Engineer из models.py. Пустая настройка означает отсутствие каталога; вымышленные ID не назначаются. Тестовые fixtures не подключаются к production автоматически. Поля доступны для чтения только backend: справочник нельзя принимать из пользовательского запроса.

## Проверка

```powershell
uv run pytest -q
uv run python tools/export_schema.py
```

Тесты используют контролируемые ответы провайдера и проверяют контракт/политику. Они НЕ измеряют точность настоящей нейросети. Реальная модель пока не проверена. После подключения необходимо отдельно прогнать синтетические fixtures и измерить точность и задержку; для этого есть `uv run python tests/evaluate_live.py --output reports/evaluation.json` (сначала создайте папку reports). Скрипт отправляет только синтетические обращения на настроенный сервер.

## Передача интегратору

Предложенный маршрут соответствует командному документу, но не добавлен в отсутствующий общий роутер. Подключение, сохранение/авторизация пользователей и merge согласуются в PR. Сроки SLA — отдельная чистая функция; изменение аварийности или назначения по таймеру запрещено. Общий журнал/уведомления реализует интегратор.

Дальнейшая серверная архитектура, открытые альтернативы и источники тестовых данных: docs/RESEARCH_AND_DEPLOYMENT.md. Все показатели памяти — расчётные ориентиры, не основание покупать сервер без нагрузочной проверки.
