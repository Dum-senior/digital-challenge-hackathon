# Приложения

## Сервис возвращает HTTP 503

**Признаки.** Сервис временно недоступен и возвращает HTTP 503.

**Проверки.** Уточнить, недоступен ли весь сервис или конкретная операция. Собрать URL без чувствительных параметров, время и идентификатор запроса. У владельца сверить состояние экземпляров, нагрузку и изменения.

**Решение и эскалация.** Если сервер указал Retry-After, учитывать его при безопасном повторе чтения. Операцию записи не повторять вслепую: сначала проверить, не появился ли результат. При массовом отказе передать дежурному.

**Источник.** <https://www.rfc-editor.org/rfc/rfc9110.html>

## В браузере ошибка сертификата

**Признаки.** ERR_CERT_DATE_INVALID или сообщение о недоверенном сертификате.

**Проверки.** Проверить дату и время устройства и точный домен; сравнить с другим корпоративным устройством.

**Решение и эскалация.** Передать владельцу сервиса ошибку и сведения о сертификате. Открывать сайт в обход предупреждения не следует.

## Форма не сохраняет запись

**Признаки.** Ошибка возникает при сохранении, остальные разделы работают.

**Проверки.** Записать обязательные поля без персональных данных, время и текст ошибки.

**Решение и эскалация.** Проверить допустимые форматы полей. Передать разработчикам воспроизводимый пример с синтетическими данными.

## Отчёт показывает устаревшие цифры

**Признаки.** Оперативная панель и экспорт за тот же период расходятся.

**Проверки.** Сравнить часовой пояс, период, время обновления и фильтры.

**Решение и эскалация.** Передать владельцу отчётности параметры и ожидаемый момент обновления выгрузки.

## HTTP 403 после обновления портала

**Признаки.** Сервер отвечает HTTP 403 на определённый раздел или действие.

**Проверки.** Сравнить один и тот же путь и действие у сотрудников с утверждённой ролью. Записать время, идентификатор запроса и версию выпуска. Проверить причину отказа в журнале приложения или шлюза.

**Решение и эскалация.** Если отказ связан с ролью, передать владельцу доступа. Если прежние разрешённые роли перестали работать после выпуска, передать разработчикам на проверку политики. Не повышать права для обхода.

**Источник.** <https://www.rfc-editor.org/rfc/rfc9110.html>

## HTTP 502 при вызове отдельной функции

**Признаки.** Шлюз вернул HTTP 502, другие страницы могут работать.

**Проверки.** Зафиксировать путь без секретов, время, идентификатор и масштаб. Владелец сравнивает журнал шлюза с журналом компонента, к которому шлюз обратился.

**Решение и эскалация.** Проверить доступность компонента и соответствие протокола на согласованном соединении. Передать ошибку владельцу компонента, если сбой повторяется. Не выдавать код 502 за доказательство перегрузки.

**Источник.** <https://www.rfc-editor.org/rfc/rfc9110.html>

## Дубли после повторного нажатия сохранить

**Признаки.** Две записи появились после долгого ожидания или обновления страницы.

**Проверки.** Сверить идентификаторы, время и исходную операцию, проверить итог до повторной отправки.

**Решение и эскалация.** Передать владельцу процесса обе записи и согласовать, какую сохранить.

## Экспорт завершается ошибкой только на большом периоде

**Признаки.** Сутки выгружаются, квартал завершается таймаутом.

**Проверки.** Зафиксировать тип отчёта, интервал, фильтры и объём успешной выгрузки.

**Решение и эскалация.** Использовать меньшие периоды, если это допускает процесс. Передать владельцу отчётности границу воспроизведения.

## Уведомление пришло, карточка не открывается

**Признаки.** Сообщение доставлено, переход по ссылке даёт ошибку или запрет.

**Проверки.** Сверить идентификатор заявки, получателя и текущую роль. Найти заявку через обычный поиск.

**Решение и эскалация.** Передать владельцу уведомлений адрес без токенов и тип ошибки. Права уточнить с диспетчером.

## PostgreSQL не подключается: SQLSTATE 08001 или 28P01

**Признаки.** Клиент сообщает 08001 при установлении соединения либо 28P01 при проверке пароля.

**Проверки.** Для 08001 сверить имя и порт сервера, проверить разрешение имени и доступность известного порта. Для 28P01 проверить, для какой учётной записи и среды приложение использует серверный секрет. Не включать пароль в заявку.

**Решение и эскалация.** Если порт недоступен, подключить сетевую группу и владельца БД. Если соединение доходит, сверить журнал сервера по времени, параметры TLS и процедуру обновления секрета. Не ослаблять аутентификацию.

**Источник.** <https://www.postgresql.org/docs/current/errcodes-appendix.html>
